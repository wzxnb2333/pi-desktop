# 会话初始化：停止、草稿恢复与任务隔离

持续 Goal 的 G-UX-04 接续验收。覆盖首次发送及恢复会话时的初始化，不将本轮成功当作整个功能台账完成。

## 已复现的问题

1. 首次发送停在 MCP 初始化时点击停止，主进程直接向尚未建立会话的 worker 发送 stop；响应构造读取 history，返回“会话尚未初始化”。工具发现和审批等待也没有统一的初始化取消链路。
2. 正常退出时虽会关闭 worker，但首次发送的 IPC 已提前确认，后台失败恢复仍未结束。最终保存早于把未执行输入放回草稿，重启后输入丢失。

## 实现

- 每个任务在开始初始化前登记取消控制器，覆盖设置快照等待、连接和工具发现。并发恢复共用一次初始化；取消释放该次实例和审批，迟到事件不能修改已恢复状态。
- 首次发送与已有运行控制器联动；尚待初始化的排队消息随当前任务停止，不在取消完成后迟到执行。恢复会话期间复用现有停止按钮，阻止把新的输入误当作运行中排队。
- 停止捕获当前初始化和 worker，先取消并等待释放，再决定是否对同一就绪实例发送 stop；不会停止其他任务或随后建立的 worker。
- 正常退出等待用户发送的后台恢复结束，再保存状态。发送确认和模型运行完成分别跟踪；未交给模型的输入恢复到草稿，重启后可由用户决定是否重发。
- 退出开始立即取消运行和初始化，拒绝新的发送；退出期间不重新安排状态广播、延迟保存或防休眠。临时侧聊销毁也取消尚未完成的初始化。
- 沿用原有 IPC、权限、草稿与停止入口，新增错误说明支持即时英文翻译。没有新增常驻按钮，没有放宽工具权限。

新增原生流程实际验证：

- 恢复时显示停止，取消保留未发送草稿；配置修正后并发恢复只建立一个 worker，正常重启保留草稿。

- 取消一个任务不影响同项目正在运行的另一个任务；主题保存不被初始化阻塞。
- 从真实输入框首次发送并确认清空后，在工具发现等待时正常退出。真实 MCP 子进程关闭，重启没有自动执行，主题和未执行输入恢复，无初始化错误。

模型、审批和 MCP 使用本地假供应商/实际 stdio fixture，没有调用真实供应商或账号。每个原生用例结束验证所属 storage 已清理，无 renderer 错误。没有进行截图或像素验收。

## 失败与修复证据

- `initial-stop-red.json`：首次新增停止回归退出 1，实际错误“会话尚未初始化”。完成初始化取消后，两个首次发送场景取得通过证据（`first-send-green.json`）。
- `startup-race-failure.json`：恢复场景通过；审批场景预期只接受 abort，但停止有可能先占用轮次快照收尾，产品明确拒绝“正在保存本轮快照”。断言现同时接受这两个合法拒绝路径，并保留不执行追加输入、不遗留审批的检查。
- `shutdown-draft-red.json`：审批取消场景通过；退出场景实际发现草稿缺失，整轮退出 1。没有降低草稿断言，修复后台发送收尾的等待顺序。
- `shutdown-draft-green.json`：只重跑退出缺陷的原始复现场景，退出 0。随后加强为真实输入框发送、发送后清空与重启后显示草稿，并加入任务错误状态检查。
- `native-green.json`：最终代码上的完整本模块 8 项定向流程通过；先前失败记录保留，不改写为通过。

上述报告位于 `.artifacts/runtime-startup-recovery/`，保留实际命令、时间和退出码。最终原生模块约 96 秒；后续单项修复仍优先按文件和名称选择，不强制每次跑整个模块。
