# 本地插件

在「Skills 与扩展 → 插件管理」选择目录或 ZIP。目录源只列出其直接子目录和 ZIP；不扫描整盘，不自动安装或授权。

包根目录使用 pi-plugin.json；ZIP 可以包含一个外层目录：

    {
      "schemaVersion": 1,
      "id": "example.plugin",
      "name": "Example",
      "version": "1.0.0",
      "skills": [{ "name": "Example skill", "path": "skill/SKILL.md" }],
      "extensions": [{ "name": "Example tools", "path": "extension.mjs" }],
      "mcp": [{ "id": "local", "name": "Local tools", "enabled": true,
        "transport": "stdio", "command": "node", "args": ["{pluginRoot}/server.mjs"] }]
    }

资源路径必须位于包内，禁止链接、目录穿越、Windows 特殊文件名和大小写冲突。Skill 需要有效 front matter；扩展为 JS/TS/MJS/CJS。每包最多 5000 项、200 MiB，每文件最多 50 MiB。依赖需随包提供；不会执行 npm 安装或生命周期脚本。

安装只复制和校验。首次启用以及更新版本需用户确认能力和内容哈希；原生扩展与 stdio 服务可以执行本机代码，只有可信包应获得授权。更新先进入候选版本；授权失败或安装失败保留当前可用版本。保留上一版本供回退。

每次任务运行使用配置快照。更新、停用或卸载不破坏运行中任务依赖的文件；下次运行加载新配置。下次应用启动只回收有所有权标记且不属于当前、候选或上一版本的目录；源目录不删除。清理失败在插件管理页面显示。运行中被修改的安装包拒绝加载，需重新安装并授权。

HTTP MCP 可在清单配置 oauth: { clientId: "", scope: "" }。授权入口出现在已启用插件卡片中；令牌由主进程加密保存，插件清单和界面不保存令牌。

已授权插件的每个 MCP 服务有独立的「连接凭据」折叠区：stdio 填环境变量，HTTP 填请求头。名称/值逐行输入，值默认遮蔽；保存替换该服务的全部连接凭据，空表单不修改。已保存的值不会返回界面，只显示是否配置；清除需要确认，不撤销 OAuth。读取或保存失败可重试，草稿保留。搜索隐藏卡片不会丢草稿，离开或停用插件前检查未保存修改；连接配置变化后必须重新核对再保存。

界面使用与运行时相同的插件目录解析，因此带 `{pluginRoot}` 的服务也可直接配置。设置仍由主进程校验并加密保存，安装未授权的插件不会因此获得访问入口。实现与验证见 [插件 MCP 连接配置](plugin-mcp-settings.md)。

临时停用插件会取消正在进行的登录，保留已保存的授权；重新启用或重启后可以继续使用。卸载删除该插件的本地 MCP 请求头/环境变量密钥与 OAuth 令牌。更新仅准备候选版本时保留当前授权；启用更新或回退时，服务地址、命令或 OAuth 身份变化会清除相应旧凭据，需要重新配置或登录。只改变安装版本目录不会清除未变更服务的密钥。

插件状态成功落盘后才向界面发布；保存失败保留原版本，凭据删除失败可重试。启动时仅清理已不属于当前配置的 MCP 凭据，已批准且暂时停用的插件仍保留授权。以上是本地凭据管理，不等同于撤销网站上的授权；远端撤销由用户主动执行。定向验证及边界见 [插件凭据生命周期](plugin-credential-lifecycle.md)。
