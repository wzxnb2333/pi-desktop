# 消息区与长会话持续迭代

真实 Goal 已创建；本轮承接已完成的聊天框增强，以下 6 项均已实现并通过最终验收。开发 Goal 与 Pi 产品内的持续目标功能相互独立。

| 编号 | 范围 | 状态 | 验收标准 |
| --- | --- | --- | --- |
| M1 | 文件保存稳定性与诊断 | 已验证 | 覆盖冲突后保存、迟到读取、并发编辑和失败恢复；没有落盘证据不得显示保存成功；未复现问题如实记录 |
| M2 | 用户正文、附件及上下文卡片 | 已验证 | 正文保持原文；来源可展开、预览和定位；实际模型上下文不丢失；重启后保持展示 |
| M3 | 消息编辑与回答重新生成 | 已验证 | 从正确轮次创建分支，保留原历史及草稿；明确工具可能执行、文件不自动回滚；权限不扩大 |
| M4 | 统一消息操作 | 已验证 | 复制、引用、分叉及重试紧凑呈现，悬停和键盘可达，中文输入法及焦点不受干扰 |
| M5 | 代码、表格与真实产物 | 已验证 | 原始代码准确复制、换行/展开、宽表局部滚动；产物通过受控路径预览或打开 |
| M6 | 长会话性能及状态 | 已验证 | 记录优化前后测量；大量轮次下保持选区、搜索定位、折叠及阅读位置 |

## 边界与工作方式

- 使用现有 Electron/React/TypeScript 和共享组件，沿用固定 Codex 26.915 参考及 Pi 品牌。
- 默认简体中文，即时英文切换；输入框四个常驻控件和隐藏的语音入口保持现状。
- 不启用开发子代理、不提交、不发布、不打包 EXE。Satang 只读。
- 每项只以真实实现与本轮验证记录验收。阶段完成后继续下一项；全部纳入项完成才结束 Goal。
- 测试使用本地假供应商和临时目录所有权机制；关闭常规截图、视频和 trace。
- 既有文件保存偶发超时不因重复运行通过就改写为已定位、已修复。

## 迭代记录

1. 已核对当前功能台账和工作区差异。开始检查保存链路并建立可重复反馈；没有改动其他会话的文件或锁文件。
2. M1 的假设依次为：迟到读取污染新保存状态；保存响应与提交内容不一致仍被当成成功；Windows 文件占用或界面时序导致偶发超时。先执行真实冲突流程 10 次，再以受控回执和迟到读取验证前两项。初次超时原因不据此推定。
3. 基线真实冲突流程 10/10 通过；随后保存专项 9/10 通过并复现同一冲突保存失败，错误明确为 Windows rename EPERM（已保留 message-save-reproduced.json）。通过真实 Windows 禁止删除共享的文件句柄再次稳定复现。修复增加最多 2 秒的有界替换重试，每次重试重新校验原文件版本，始终保留原子替换且不删除目标文件。
4. 另有三个先失败后通过的回归：过大/含空字符编辑会被截断回执吞掉草稿；错误回执被当成保存成功；旧读取失败污染新保存状态。现在拒绝无法完整表示的编辑、校验回执并保留草稿，保存操作提供 ID、版本和耗时诊断。
5. 修复后保存与上下文专项 12/12 通过（message-M1-M2-results.json）。上下文来自发送时的结构化元数据和原文摘要校验，旧消息没有可靠元数据时保持原文，绝不猜测分隔符。队列编辑、重排和重启保留来源身份。
6. 消息编辑/重新生成从实际 session 的正确用户轮次之前创建分支，首次消息的空分支也落盘；原 session 不变、不启动额外工具进程、不复制 Goal/自动化/队列等运行状态。附件独立复制；引用重校验；错误保留新分支草稿。真实原生分支、重启、重发、附件复制、重复请求和运行中拒绝均已通过定向用例，仍需合并回归。
7. 180 轮含代码/表格的开发模式基线中，8 次无关状态更新的 React commit 中位数约 512ms。将 Markdown 解析/高亮按文本缓存后首轮测得约 49ms；节点总数保持 15669，不卸载历史 DOM。继续检查 1000 轮下的选区、阅读位置、搜索及双语布局。
8. 1000 轮下的选区、阅读位置、代码换行状态、350/999 轮搜索和即时语言切换通过；深浅主题 × 中英文 × 三种宽度的 12 个代码/表格布局用例全部通过。复制断言只归一化 Windows 剪贴板的 CRLF，保留制表符、空行与 Unicode 的完整比较。
9. 原生图片预览/重新生成验收发现新的分支没有出现在旧 Renderer 闭包中，导致已发送草稿未清空。改用最新草稿的函数更新，只清除已发送内容；校验发送回执，未知状态不丢草稿、不自动重发。切换分支后仍显示发送失败。图片重启、UI 创建并发送、来源变化后的失败与草稿重启恢复均通过。
10. 桌面单元测试 294/294 通过，桌面类型检查与根级完整检查退出码均为 0；根检查未自动修改文件，执行前后原有 Git 差异哈希一致。完整桌面非视觉回归仍在执行，未提前登记完成。
11. 首轮完整非视觉回归 508 项中 507 通过、1 失败，确认为后台 Git 读取与暂存争用 index.lock。新测试以只改变文件时间戳的方式稳定复现索引被只读查询改写；先证明 status 与 diff 两条刷新路径，再同时关闭可选锁和 diff 自动刷新。保留所有显式写操作的必要锁，不删除其他进程的锁文件。
12. 补强上下文快照搜索后，复现查询词错误命中卡片提示语而非原文的问题。将提示与操作控件排除出搜索文本，验证高亮落在快照原文中；另走通过期引用的分支草稿重启、刷新引用和成功重发。
13. 修复后的 26 项 Git、消息、审查、搜索及 Worktree 定向回归通过。新增索引锁用例及完整桌面单元测试 295/295 通过，根检查再次通过。缓存清理测试必须在 Electron 回归结束后串行执行；并行运行时保护机制曾拒绝清理，没有绕过保护。
14. 第二轮完整回归 507/508 通过，发现新网页标签的 IPC 尚未完成时，后续地址输入仍可能进入旧标签。使用受控的延迟创建重现可编辑旧输入框的问题；创建、恢复和关闭期间禁用地址编辑，响应应用后恢复，失败保留原草稿。包含成功和失败路径的新回归与原生浏览器、面板的 15 项定向测试全部通过，桌面类型检查通过；保留第二轮失败报告，再以最终源码执行完整回归。
15. 最终完整非视觉回归 509/509 通过，0 失败、0 跳过、0 flaky，退出码 0；桌面类型检查、根级完整检查和桌面构建均退出 0。287 份源码的 SHA-256 与验收前冻结记录一致，原有受 Git 跟踪的差异逐字节保持不变。验收结束后清理 1 个已确认属于本地测试的旧目录，释放 18,791,436 字节；复查没有剩余的匹配测试临时目录，没有跳过项。
